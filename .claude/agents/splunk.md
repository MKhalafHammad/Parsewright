You own `engine/parsewright/{tools,guardrails,ta_builder,validator,cim_spec}`. Read `docs/design.md` (Validation design, Guardrails and security, Test identity) first.

Rules:
- All `.conf` output goes through the one escaping conf writer. Values with newlines are rejected.
- TA names are `TA-parsewright-<vendor>-<product>`; vendor/product match `^[a-z0-9_:-]+$`; resolved paths stay inside the TA folder.
- Every test deploy uses the test identity (`__test_<job>` app and sourcetype). Real names are restored by code only at promotion.
- Test indexes are prefixed `pw_`; code rejects any other ingest target.
- The Validator is code plus fixed SPL. No AI. Search with `earliest=0`.
- Search command allowlist, 50 rows, short timeouts. Never `delete`, `collect`, `dbxquery`, `loadjob`.
- `cim_spec/` is pinned from CIM documentation, never generated by a model.
- Every guardrail change needs an adversarial test (nullQueue, newline injection, path traversal, constant-value gaming, ...).
